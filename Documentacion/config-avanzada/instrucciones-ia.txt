=======================================================

PROPOSITO DE ESTE DOCUMENTO
----------------------------

Este documento proporciona contexto completo y directrices para que asistentes 
automatizados de desarrollo (como ChatGPT, Claude, Copilot, etc.) puedan entender

================================================================================
CONTEXTO GENERAL DEL PROYECTO
================================================================================

NOMBRE: StudentsPoint
TIPO: Progressive Web Application (PWA)
STACK: Django 5.2 (Backend) + Vanilla JavaScript (Frontend)
PROPOSITO: Plataforma integral para estudiantes universitarios
DESARROLLO: Proyecto de Capstone - Ingenieria en Informatica


================================================================================
ARQUITECTURA DEL PROYECTO
================================================================================

1. PATRON GENERAL:
   - Backend: API REST con Django REST Framework
   - Frontend: SPA (Single Page Application) con JavaScript vanilla
   - Autenticación: JWT (JSON Web Tokens)
   - Base de datos: SQLite (dev) / PostgreSQL (prod)
   - Cache: Redis
   - Tareas asíncronas: Celery

2. COMUNICACION FRONTEND-BACKEND:
   - Frontend hace peticiones HTTP a /api/*
   - Backend responde con JSON
   - Autenticación mediante header: Authorization: Bearer <token>
   - CORS configurado para desarrollo y producción

3. APPS DJANGO (MODULAR):
   studentspoint/apps/
   ├── accounts/       # Autenticación y usuarios
   ├── campuses/       # Campus y recorridos virtuales
   ├── forum/          # Foros de discusión
   ├── health/         # Health checks
   ├── market/         # Marketplace
   ├── notifications/  # Notificaciones push
   ├── otec/           # Cursos
   ├── polls/          # Encuestas
   ├── portfolio/      # Portafolios profesionales
   ├── reports/        # Sistema de tickets
   ├── schedules/      # Horarios
   └── wellbeing/      # Bienestar estudiantil

DIRECTRICES DE CODIGO BACKEND (DJANGO)
================================================================================

1. MODELOS (models.py):
   
   CONVENCIONES:
   - Usar PascalCase para nombres de clases
   - Incluir __str__ para representación legible
   - Usar related_name descriptivos en ForeignKey
   - Incluir help_text en campos cuando sea útil
   - Ordenar campos: campos básicos → relaciones → metadatos
   
   EJEMPLO CORRECTO:
   ```python
   class Post(models.Model):
       titulo = models.CharField(max_length=200)
       cuerpo = models.TextField()
       usuario = models.ForeignKey(
           settings.AUTH_USER_MODEL,
           on_delete=models.CASCADE,
           related_name="posts"
       )
       created_at = models.DateTimeField(auto_now_add=True)
       
       class Meta:
           ordering = ['-created_at']
       
       def __str__(self):
           return self.titulo
   ```

2. SERIALIZERS (serializers.py):
   
   CONVENCIONES:
   - Un serializer por modelo principal
   - Usar serializers anidados para relaciones
   - Incluir validación personalizada en validate_*
   - Meta.fields explícito (evitar '__all__' en producción)
   
   EJEMPLO CORRECTO:
   ```python
   class PostSerializer(serializers.ModelSerializer):
       usuario = UserSerializer(read_only=True)
       
       class Meta:
           model = Post
           fields = ['id', 'titulo', 'cuerpo', 'usuario', 'created_at']
           read_only_fields = ['created_at']
       
       def validate_titulo(self, value):
           if len(value) < 5:
               raise serializers.ValidationError("Título muy corto")
           return value
   ```

3. VISTAS (views.py):
   
   CONVENCIONES:
   - Preferir ViewSets para CRUD completo
   - Usar APIView para endpoints personalizados
   - Aplicar permisos apropiados
   - Manejar errores explícitamente
   - Incluir docstrings para documentación automática
   
   EJEMPLO CORRECTO:
   ```python
   class PostViewSet(viewsets.ModelViewSet):
       """
       ViewSet para gestión de posts en foros.
       
       list: Listar todos los posts
       create: Crear nuevo post
       retrieve: Obtener post específico
       update: Actualizar post
       destroy: Eliminar post
       """
       queryset = Post.objects.select_related('usuario')
       serializer_class = PostSerializer
       permission_classes = [IsAuthenticated]
       filter_backends = [DjangoFilterBackend, SearchFilter]
       search_fields = ['titulo', 'cuerpo']
       
       def perform_create(self, serializer):
           serializer.save(usuario=self.request.user)
   ```

4. URLS (urls.py):
   
   CONVENCIONES:
   - Usar routers para ViewSets
   - Nombres descriptivos para rutas
   - app_name para namespacing
   
   EJEMPLO CORRECTO:
   ```python
   from rest_framework.routers import DefaultRouter
   from .views import PostViewSet
   
   app_name = 'forum'
   
   router = DefaultRouter()
   router.register(r'posts', PostViewSet, basename='post')
   
   urlpatterns = router.urls
   ```

5. ADMIN (admin.py):
   
   CONVENCIONES:
   - Registrar todos los modelos
   - Configurar list_display para vista de lista
   - Incluir search_fields y list_filter cuando sea útil
   
   EJEMPLO CORRECTO:
   ```python
   @admin.register(Post)
   class PostAdmin(admin.ModelAdmin):
       list_display = ['titulo', 'usuario', 'created_at', 'estado']
       list_filter = ['estado', 'created_at']
       search_fields = ['titulo', 'cuerpo']
       date_hierarchy = 'created_at'
   ```

3. MANEJO DE AUTENTICACION:
   
   PATRON ESTANDAR:
   ```javascript
   // Obtener token
   function getAuthToken() {
       return localStorage.getItem('access_token');
   }
   
   // Verificar autenticación
   function checkAuth() {
       const token = getAuthToken();
       if (!token) {
           window.location.href = '/login.html';
           return false;
       }
       return true;
   }
   
   // Headers para peticiones autenticadas
   function getAuthHeaders() {
       return {
           'Authorization': `Bearer ${getAuthToken()}`,
           'Content-Type': 'application/json'
       };
   }
   ```

4. MANEJO DE ERRORES:
   
   PATRON ESTANDAR:
   ```javascript
   async function fetchData() {
       try {
           const response = await fetch(url, options);
           
           if (!response.ok) {
               if (response.status === 401) {
                   // Token expirado
                   localStorage.removeItem('access_token');
                   window.location.href = '/login.html';
                   return;
               }
               throw new Error(`Error ${response.status}`);
           }
           
           return await response.json();
       } catch (error) {
           console.error('Error:', error);
           showError('Ocurrió un error. Por favor intenta nuevamente.');
       }
   }
   ```

5. DOM MANIPULATION:
   
   CONVENCIONES:
   - Usar querySelector/querySelectorAll
   - Evitar innerHTML cuando sea posible (usar textContent)
   - Limpiar event listeners cuando no se necesiten
   
   EJEMPLO CORRECTO:
   ```javascript
   function renderPosts(posts) {
       const container = document.getElementById('posts-container');
       container.innerHTML = ''; // Limpiar contenido previo
       
       posts.forEach(post => {
           const postElement = document.createElement('div');
           postElement.className = 'post-card';
           
           const title = document.createElement('h3');
           title.textContent = post.titulo;
           
           const body = document.createElement('p');
           body.textContent = post.cuerpo;
           
           postElement.appendChild(title);
           postElement.appendChild(body);
           container.appendChild(postElement);
       });
   }
   ```


================================================================================
SISTEMA DE AUTENTICACION
================================================================================

1. FLUJO DE LOGIN:
   
   a) Usuario envía credenciales a /api/auth/login/
   b) Backend valida y retorna access_token y refresh_token
   c) Frontend guarda tokens en localStorage
   d) Frontend incluye access_token en todas las peticiones
   
   IMPLEMENTACION:
   ```javascript
   async function login(email, password) {
       const response = await fetch('/api/auth/login/', {
           method: 'POST',
           headers: { 'Content-Type': 'application/json' },
           body: JSON.stringify({ email, password })
       });
       
       if (response.ok) {
           const data = await response.json();
           localStorage.setItem('access_token', data.access);
           localStorage.setItem('refresh_token', data.refresh);
           window.location.href = '/index.html';
       }
   }
   ```

2. FLUJO DE REGISTRO:
   
   a) Usuario envía datos a /api/auth/register/
   b) Backend crea usuario y retorna tokens
   c) Mismo flujo que login
   
3. GOOGLE OAUTH:
   
   a) Frontend redirige a /api/auth/google/login/web/
   b) Google autentica y redirige a callback
   c) Backend procesa y redirige con tokens
   d) Frontend captura tokens de URL

4. REFRESH TOKEN:
   
   Cuando access_token expira (401):
   ```javascript
   async function refreshToken() {
       const refresh = localStorage.getItem('refresh_token');
       const response = await fetch('/api/auth/refresh/', {
           method: 'POST',
           headers: { 'Content-Type': 'application/json' },
           body: JSON.stringify({ refresh })
       });
       
       if (response.ok) {
           const data = await response.json();
           localStorage.setItem('access_token', data.access);
           return true;
       }
       return false;
   }
   ```


================================================================================
SISTEMA DE FOROS
================================================================================

1. ESTRUCTURA:
   - Foro: contenedor por sede/carrera
   - Post: publicación en un foro
   - Comentario: respuesta a un post
   - Voto: upvote/downvote en post

2. MODERACION AUTOMATICA:
   - Lista de palabras prohibidas (BANNED_WORDS)
   - Lista de palabras que requieren revisión (MODERATION_WORDS)
   - Estados: publicado, revision, oculto, rechazado
   - Posts con palabras prohibidas van a revisión automáticamente

3. ANONIMATO:
   - Campo anonimo en Post
   - Si es anónimo, no mostrar usuario en frontend
   - Moderadores pueden ver usuario real

4. API ENDPOINTS:
   GET    /api/foros/                    # Lista de foros
   GET    /api/foros/{id}/posts/         # Posts de un foro
   POST   /api/posts/                    # Crear post
   GET    /api/posts/{id}/                # Detalle de post
   POST   /api/posts/{id}/votar/         # Votar post
   POST   /api/posts/{id}/comentar/      # Comentar post

PWA Y SERVICE WORKER
================================================================================

1. REGISTRO DE SERVICE WORKER:
   
   En main.js o pwa.js:
   ```javascript
   if ('serviceWorker' in navigator) {
       navigator.serviceWorker.register('/sw.js')
           .then(reg => console.log('SW registered'))
           .catch(err => console.error('SW error:', err));
   }
   ```

2. ESTRATEGIA DE CACHE:
   
   En sw.js:
   - Cache-first para archivos estáticos (CSS, JS, imágenes)
   - Network-first para API calls
   - Fallback a cache si network falla
   
   EJEMPLO:
   ```javascript
   self.addEventListener('fetch', event => {
       if (event.request.url.includes('/api/')) {
           // Network-first para API
           event.respondWith(
               fetch(event.request)
                   .catch(() => caches.match(event.request))
           );
       } else {
           // Cache-first para estáticos
           event.respondWith(
               caches.match(event.request)
                   .then(response => response || fetch(event.request))
           );
       }
   });
   ```

3. MANIFEST.JSON:
   - Configurado con iconos múltiples tamaños
   - Shortcuts a funcionalidades principales
   - theme_color y background_color configurados

SOLUCIONES A PROBLEMAS COMUNES
================================================================================

1. ERROR: Token inválido o expirado
   SOLUCION: Implementar refresh token automático o redirigir a login

2. ERROR: CORS blocking requests
   SOLUCION: Verificar CORS_ALLOWED_ORIGINS en settings
   
3. ERROR: 404 en archivos estáticos
   SOLUCION: Ejecutar collectstatic
   
4. ERROR: Migraciones conflictivas
   SOLUCION: python manage.py migrate --merge

5. ERROR: Service Worker no actualiza
   SOLUCION: Cambiar versión en sw.js y hacer hard refresh
